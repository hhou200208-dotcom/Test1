## 1. 我核对过的事实（基于本仓库代码，非主观臆测）

在给意见前，我核对了实现，以下是**与正文表述存在差距**的客观事实，Codex 可复核：

1. **N=192 是投影，不是原生评估。** `core/config.py` 中 `N_PLANES=5, N_SATS_PER_PLANE=5, N_SATS=25`；`eval_multiseed.py` 用的就是该默认 `Config`（未覆盖 `N_SATS`）。`WORK_LOG.md` L227–229 明确记载：系统总量（能耗/时延）= **N=25 实测 ×(192/25)=×7.68**，率/per-sat 量（满意度/HL）按 N-不变直接标 N=192；原生 N=192 只跑过 **500 槽** 做 sanity check。
   - 交叉验证数值：消融表能耗 `6957 kJ` ≈ N=25 的 `912 kJ × 7.68 = 7004`；HL `183` ≈ 内部记录 `~180`。**吻合投影，不是原生 5400 槽 ×10 seed。**
   - **但 `demo3_fin2.tex` 正文/表注/消融表 caption 全无投影披露**（`grep 投影/projec/scaling` 只命中 DoD 区间投影，与此无关）。仓库 `figures_paper/` 图注里本来有 "projected from validated linear scaling"，**这版正文把它丢了**。

2. **13% 链路违约（正文已披露，L1487–1489）。** 参考实现放宽了"单链路单任务"抽象，约 13% 转发落在 `名义传输量 > b_nm·τ` 的链路–时隙，卸载能力/时延为偏乐观估计。诚实，但系统性偏差。

3. **奖励里电池信号疑似"双计"。** `core/satellite.py:558` `slot_health_loss = slot_delta_l_comp + slot_delta_l_trans`，而 `slot_delta_l_* = L'(DoD)·ΔDoD`（`core/lyapunov.py:114/118`）——即 `R^obj` 里的"实测边际寿命消耗" `H_n` 与 `r^base`（`R^prior`）里的一阶代理 `ΔL` **同源同形**。电池信号在 per-task（R^prior）与 slot（R^obj）两个粒度上各计一次，可能放大电池惩罚（见 §4.4，且可能解释消融里 NoDoD 能耗翻倍的异常）。

4. **Codex 已在参与评审。** `eval_multiseed.py` 抬头注释 `closes Codex #1 (n=1 -> CI)`——n=1→10 seed 的置信区间问题已修。说明协作机制已跑通，本文件延续该编号习惯。

### 3.2 【新颖性定位】需要一个"能被记住的东西"

顶会/正刊的隐性门槛：读者读完能用一句话复述你的**核心贡献**。当前三个 ingredient（MAPPO、Lyapunov 型塑形、虚拟队列 `Z_n`、DVFS 校准）**各自都是已知技术**，"组合"不足以撑顶会。二选一补强：

- **路线②（实验碾压）**：不做理论，就把实验做到**顶会级厚度**（见 §5）——完整 Pareto 前沿、V/η/battery-weight 敏感性、可扩展性曲线、学习曲线、更多 SOTA 基线。用"经验说服力"换新颖性。

- 摘要/引言的"维持**有竞争力**的完成率与时延"措辞在替审稿人做价值判断。审稿人会追问：**这个 operating point 凭什么是好的？**

## 4. 算法设计部分·逐点技术意见（用户重点关注，按重要度）

### 4.1 P1 与实际优化目标之间缝隙过多，且全靠免责声明填

正文用了至少 5 处"不等价/不构成/仅作先验/相对指标"来隔离 P1 与实现：
- P1 是长期**时均**代价，PPO/GAE 优化的是 `γ=0.99` **折扣**回报（L1275–1276 自认）；
- 塑形奖励**非** potential-based，最大化复合奖励**不等价**于解 P1（L1116、L1202、L1274）；
- 截止时间是**动作筛选**而非硬约束；队列稳定是**经验指标**非保证；`Z_n` 不进 P1 约束。

**问题**：当 P1 与你真正求解的东西关系这么松，P1 的存在意义被削弱，读起来像"摆一个漂亮的优化问题然后声明我不解它"。**建议**：
- 要么**弱化 P1 的地位**，老实说"我们不优化 P1，P1 只用于界定物理约束与指标口径"，把 P1 降格为"问题背景/指标定义"，主线直接讲 Dec-POMDP + 塑形；
- 要么**补 §3.2 路线①的 gap bound**，把这些"不等价"从定性免责升级为定量误差项。二者至少占一头，否则审稿人会抓"P1 是稻草人"。

### 4.2 缺一个干净的 Dec-POMDP 定义

正文有 P1（控制问题）和一堆奖励式，但**没有把 MAPPO 实际求解的 Dec-POMDP 显式列清**：`⟨N, S, {A_n}, P, {O_n}, {R_n}, γ⟩` 各元素、观测函数 `O_n`（一跳邻域到 `s_n(t)` 的映射）、转移 `P`（就是队列+DoD 动态）、折扣 `γ`。**建议**加一个 boxed 定义或一张表，把"环境=系统模型、智能体=卫星、观测=式 state、动作=式 feasible_actions、奖励=式 reward_twolayer、转移=式 QF/QB/DoD"一一对齐。这是 MARL 论文的**标准动作**，缺了显得不规范。

### 4.3 时隙级信用分配是启发式且有偏（需正视/消融）

- 现状（L1251–1253、Alg.1 L1439）：同一时隙内所有任务的奖励聚合成 `R_n(t)`，共享**同一个** slot-level GAE 优势 `Â_t`，自认"启发式时隙级信用分配，非标准逐动作 MAPPO 推导"。
- **问题**：槽内任务是**序贯决策 + 临时状态**（`hat{N}^B_n`、`hat{Z}_n` 随决策更新，L1079、Alg.1 L1362-1377），后决策任务的可行集/代价依赖先前动作 → 这是一个**槽内序贯 MDP**，却用一个共享标量优势去更新所有动作的 `π_θ(a_i|s)`，梯度**有偏**（把 A、B 两个动作的功劳混在一起）。
- **建议**：
  - 至少补一段**偏差讨论**：为什么这个偏差可接受（例如槽内任务数期望小、共享优势是无偏优势的低方差代理……给个论证）。
  - 更好：**做一个消融**——per-task 优势（把槽内当序贯，逐动作 bootstrap）vs slot-level 优势，报告二者性能。若 slot-level 不劣，就用数据堵住这个洞；若更差，说明这是折中。
  - 这是**算法部分最容易被 MARL 审稿人挑**的点，务必先手处理。

### 4.4 奖励里电池信号疑似双计（有代码依据）

见 §1.3：`H_n`（进 `R^obj`）与 per-task `ΔL`（进 `R^prior`）同源同形（都是 `L'(DoD)·ΔDoD` 之和）。

- **风险**：同一物理量在两个粒度各罚一次 → 电池项**实际权重被放大**，可能是消融里"关掉后能耗翻倍"过猛的原因之一。
- **也可能是有意设计**（proxy 引导 per-task 信用、H_n 提供 slot outcome）。但正文把 `H_n` 称"**实测**边际寿命消耗"（L1111），而代码里它就是一阶代理之和，不是 `L(DoD(t+1))−L(DoD(t))` 的真实差分——"实测"用词**过强**。
- **建议**：(i) 澄清 `H_n` 定义与 `ΔL` 的关系，明确是否刻意双计；(ii) 若要"实测"，`H_n` 改用真实 `L` 差分 `L(DoD_n(t+1))−L(DoD_n(t))`，与 per-task 一阶代理**解耦**，这样 `R^obj`（真实 outcome）/`R^prior`（一阶代理引导）分工才干净；(iii) 补一个"电池项权重"敏感性，证明结论不靠这个双计。

### 4.5 "Lyapunov / LyaMAPPO" 命名 vs 无 drift 保证

正文反复声明"不构造严格漂移加惩罚分解""不产生经典 Lyapunov 渐近权衡"。既然如此，**把方法命名为 LyaMAPPO、通篇"Lyapunov 启发"** 会招来"名不副实"的审稿意见——有的审稿人对"XX-inspired 但没有 XX 理论"很敏感。**二选一**：
- 补最小限度的漂移分析（§3.2 路线①），让"Lyapunov"名副其实；
- 或坦然改名/弱化（如"queue-and-DoD-aware reward shaping"），别把卖点押在一个自己都声明不成立的框架上。

### 4.6 超参与归一化尺度过多、正文无敏感性

`V=50, η=0.5, (w_d,w_to,w_re,w_h,w_q)=(10,5,5,2,0.05), λ_s, ρ_H`，加上 `L_max^new, ΔDoD_max, Z_max, δ_max, δ_comp_max, H_norm` 一堆归一化尺度。**正文只给了 K_max 敏感性**。审稿人会质疑鲁棒性与"是否精心调参才好看"。**建议**至少补 `V`（队列 vs 电池权衡）与 `η`（能量赤字）的敏感性曲线（`sensitivity_v_paper.py` 已能产出），证明性能对这些权重不敏感或存在稳定区间。

### 4.7 序贯槽内决策的一致性/可复现细节

- 遍历顺序 EDF（`w^i` 升序，`s^i` 打破平局，L1080-1082）——训练/评估同序保证可复现，好。但**该顺序本身是策略的一部分**，会影响结果；建议正文点明"顺序=固定 EDF 先验，非学习"，并可选做"随机顺序 vs EDF"小消融，说明鲁棒性。
- 本地动作的 DoD 边际（式 delta_dod_comp_task）用**下一时隙预测频率的前后差**，且频率饱和时可能为 0（L818-820 已讨论）。这一段逻辑正确但绕，建议配一张"任务级边际代价计算流程"小图。

### 4.8 状态特征"从略"伤可复现

L1086-1088 承认"实现中的状态还包含若干派生工程特征……此处从略"。顶会/artifact 评审要求可复现，**"从略"= 无法复现**。**建议**把完整状态向量（含所有工程特征、维度、归一化方式）放进**附录或开源 README**，正文可只列主分量但必须指向完整定义。

### 4.9 动作空间与"被动保留"的形式化

"全零决策=被动保留在转发队列，非策略动作"这一约定在 L1010-1011、L1043、L1104 出现三次，说明作者也觉得别扭。从 RL 角度，"不选任何可行动作"其实**等价于一个隐式 wait 动作**。**建议**要么显式引入 `wait` 动作纳入动作空间（更干净，且能学"何时该等"），要么在附录用一句形式化定义 `a=∅` 的语义和它对 `π_θ` 归一化的影响，别散在正文三处口头约定。
